# 비콘 배치 추천 프로그램

롯데몰 광교 BLE 실내측위 · 아주대 전자과 Brain 팀 / Google–아주대 AI융합캡스톤디자인

**백엔드가 없는 정적 웹앱입니다.** 계산 엔진이 브라우저 안에서(Web Worker) 돌기 때문에
Vercel·Netlify·GitHub Pages 어디에나 그대로 올라가고, 서버 요금이 들지 않습니다.

## 1. 내 컴퓨터에서 실행

Node.js 18 이상이 필요합니다. ([nodejs.org](https://nodejs.org) LTS)

```bash
npm install        # 처음 한 번
npm run dev        # http://localhost:5173
```

계산 엔진만 검증하려면:

```bash
npm run verify     # 유니티 C# 원본과 수치 대조 + 전 층 실제 계산
```

## 2. Vercel 배포 (공유 URL 만들기)

### 준비 — GitHub 에 올리기

```bash
git init
git add .
git commit -m "비콘 배치 추천 프로그램"
```

GitHub 에서 새 저장소를 만들고, 안내에 나오는 두 줄을 붙여넣습니다.

```bash
git remote add origin https://github.com/<아이디>/beacon-planner.git
git push -u origin main
```

### 배포

1. [vercel.com](https://vercel.com) → **Continue with GitHub** 로 가입
2. **Add New → Project** → 방금 만든 저장소 **Import**
3. 설정 화면이 뜨는데 **아무것도 건드리지 말고** Deploy
   (Vite 프로젝트라 Framework Preset·빌드 명령·출력 폴더가 자동으로 잡힙니다)
4. 1분쯤 뒤 `https://beacon-planner-....vercel.app` 주소가 나옵니다

이후로는 `git push` 할 때마다 자동으로 다시 배포됩니다.

> **Netlify 나 GitHub Pages** 도 똑같이 됩니다.
> 빌드 명령 `npm run build`, 배포 폴더 `dist` 로만 맞춰주면 됩니다.
> (GitHub Pages 는 하위 경로에 올라가므로 `vite.config.js` 에
> `base: '/저장소이름/'` 을 추가해야 합니다)

### 임시로 지금 화면만 보여주고 싶다면

배포 없이 내 컴퓨터 화면을 잠깐 공유하는 방법입니다. 내 컴퓨터가 켜져 있는 동안만 살아있습니다.

```bash
npm run build && npm run preview     # localhost:4173
# 다른 터미널에서
npx localtunnel --port 4173
```

`cloudflared tunnel --url http://localhost:4173` 이나 `ngrok http 4173` 도 같습니다.

## 3. 화면 사용법 — 5단계

| 단계 | 위치 | 하는 일 |
|---|---|---|
| ① 비콘 제원 | 좌측 상단 | 모델명, **단가**, 송신출력, 1m 기준세기, 경로손실 지수, 임계값 |
| ② 도면 | 자동 | 롯데몰 광교 B1~4F 도면이 앱에 들어 있음. 층 버튼으로 전환 |
| ③ 추천 계산 | **[③ 배치 계산]** | 층별 모드에 따라 배치를 계산하고 지표·비용을 낸다 (약 3초) |
| ④ 커스터마이징 | 캔버스 | **드래그** 이동 / **Shift+클릭** 추가 / 선택 후 **Delete** 삭제 / **고정** |
| ⑤ 저장 | **[JSON 저장]** | 비콘 + 제원 + 설정 + 지표 + 비용을 한 파일로 |

**고정(Lock)** 을 걸어둔 비콘은 다시 [배치 계산] 을 눌러도 그 자리를 지키고,
나머지만 재계산합니다. 직접 옮기거나 추가한 비콘은 자동으로 고정됩니다.

배치를 손으로 고친 뒤에는 **[현재 배치 재평가]** 를 눌러야 커버리지·비용
숫자가 갱신됩니다.

계산은 백그라운드 스레드에서 돌기 때문에, 계산 중에도 층을 넘겨보고 화면을
조작할 수 있습니다.

### 화면 표시

| 색 | 뜻 |
|---|---|
| 🔵 파랑 | 측위용 격자 비콘 |
| 🟠 주황 | 수직동선 앞 필수 비콘 / 도면의 승강장 축 (EV·ST·ES) |
| 🔴 빨강 | 체크포인트 비콘 |
| 🟢 초록 | 사용자가 고정한 비콘 |
| 빨간 점선 원 | 도면상 BOH 안에 잡힌 승강장 — 좌표 확인 필요 |

## 4. 두 가지 모드 — 지상과 지하를 다르게 푸는 이유

### 지하 = 측위 모드 (positioning)

GPS 가 안 잡히므로 비콘만으로 위치를 알아내야 합니다. 그러려면:

- **비콘이 3개 이상 동시에 보여야** 삼변측량이 성립합니다. 1개만 보이면
  "근처에 있다" 밖에 모릅니다.
- **그 3개가 일직선에 가까우면 해가 발산합니다.** 이걸 수치로 나타낸 게
  HDOP 이고, 위성측위의 GDOP 과 같은 개념입니다.
  `HDOP = √(trace((HᵀH)⁻¹))`, H 의 각 행은 측정점→비콘 단위벡터.

그래서 목적함수를 "신호가 닿는 면적"이 아니라 **"HDOP 이 괜찮은 상태로
3개 이상 보이는 면적"** 으로 잡았습니다. 단순 커버리지로 최적화하면 숫자는
예쁘게 나오는데 실제 측위 오차가 몇 미터씩 튑니다.

탐욕법(greedy)은 최대커버리지 문제에서 **(1−1/e) ≈ 63% 근사보장**이 있는
표준 기법입니다. 보고서에 알고리즘 근거로 쓸 수 있습니다.

### 지상 = 체크포인트 모드 (checkpoint)

GPS 로 수평 위치가 잡히므로, 비콘은 **"몇 층인가"** 만 답하면 됩니다.
층이 바뀌는 곳은 엘리베이터·에스컬레이터·비상계단뿐이므로 그 승강장에만
비콘을 둡니다.

에스컬레이터 상행/하행 쌍은 1.5 m 밖에 안 떨어져 있어서 최소 이격 규칙이
자동으로 하나로 합칩니다 (= 승강장 1곳당 1개). 엘리베이터와 비상계단이
같은 홀에 있으면 역시 하나가 둘을 함께 담당하고, `Elevator+Stair` 로 표시됩니다.

**이 구분 하나로 비콘이 488개 → 98개로 줄어듭니다.**

## 6. ⚠️ 꼭 알아야 할 두 가지

### (1) RF 파라미터가 결과를 통째로 뒤집습니다

측위 임계값을 -80 dBm 으로 두고 돌렸을 때 3중 커버리지가 6~34% 였는데,
-85 dBm 으로 고치니 95% 가 나왔습니다. **5 dB 차이입니다.**

지금 값은 2.4 GHz 실내 전파의 일반적인 문헌값이지 롯데몰 광교의 실측값이
아닙니다. 캘리브레이션 전까지 이 숫자들은 **상대 비교용이지 절대값이 아닙니다.**

**측정 방법** — 비콘 1개를 3 m 천장에 붙이고, 스마트폰으로
1·2·3·5·8·12·20 m 지점에서 각각 30초씩 RSSI 를 기록합니다.

- 1 m 값의 중앙값 → `1m 기준세기` (Tx 출력만큼 빼서 환산)
- 거리 vs RSSI 를 `RSSI = A − 10·n·log₁₀(d)` 로 회귀 → 기울기가 `경로손실 지수 n`
- 벽 하나를 사이에 두고 같은 거리에서 재측정 → 차이가 그 벽의 손실 dB

### (2) 1F 에서 층을 오판할 수 있습니다

화면 우측 "층 판별 정확도" 표가 이걸 보여줍니다.

| 층 | 신호 있음 | 정확도 | 오판 지점 |
|---|---|---|---|
| B1 | 100.0% | 100.0% | 0 |
| **1F** | 88.9% | **97.7%** | **48** |
| 2F | 80.6% | 100.0% | 0 |
| 3F | 83.0% | 99.8% | 4 |
| 4F | 74.8% | 99.2% | 7 |

**원인**: B1 은 측위용이라 비콘이 66개 깔려 있고, 1F 는 체크포인트라 10개뿐입니다.
1F 에서 체크포인트로부터 먼 지점에 서 있으면, 바로 아래 B1 비콘이 슬래브를
뚫고 더 세게 잡혀서 "B1 에 있다"고 오판합니다. 밀집된 층 바로 위가 취약합니다.

**해결책** — 앱에서 층을 "가장 센 비콘의 층" 으로 정하면 안 됩니다.
비콘 ID 에 층이 들어 있으므로(`B1-01`, `1F-CP01`), **상태 기계**로 풀어야 합니다:

> 현재 층을 유지하다가, **체크포인트 비콘을 통과했을 때만** 층을 바꾼다.

이러면 1F 한복판에서 B1 신호가 세게 잡혀도 층이 튀지 않습니다.
지상은 어차피 GPS 로 수평 위치를 아니까, 비콘은 "층 전환 이벤트"로만 쓰는
게 맞습니다. 이 설계가 곧 체크포인트 모드를 쓰는 이유이기도 합니다.

### (3) 임대매장 내부에는 보통 설치할 수 없습니다

몰에서 우리가 시공할 수 있는 곳은 **공용부(통로·홀)** 이고, 임대매장 안은
테넌트 공간이라 별도 협의가 필요합니다. 그래서 기본값은 **공용부만**
후보로 삼습니다. (최적화 설정 → `임대매장 내부에도 설치`)

이 제약이 결과를 크게 바꿉니다.

| B1 기준 | 비콘 | 3중 커버리지 | 평균 HDOP |
|---|---|---|---|
| 공용부만 (기본) | 66 | 82.3% | 0.90 |
| 매장 내부 포함 | 55 | 95.4% | 1.14 |

통로에서만 쏘면 매장 깊숙한 안쪽까지 3개를 동시에 보이게 하기가
어렵습니다. 비콘을 더 넣어도(66개까지 늘려도) 82% 에서 더 안 오릅니다 —
개수 문제가 아니라 **놓을 수 있는 자리가 통로로 제한된 기하 문제**입니다.

보고서에는 이렇게 쓰는 게 정확합니다: "공용부 시공만 가능한 조건에서
3중 가시성 커버리지의 상한은 82% 수준이며, 매장 내부 시공이 허용되면
95% 까지 확보 가능하다."

## 7. 알려진 한계 (보고서에 정직하게 쓸 부분)

1. **RF 파라미터가 문헌값입니다.** (위 6-(1))
2. **사람과 집기의 감쇠를 넣지 않았습니다.** 2.4 GHz 는 인체(수분)에 특히
   잘 흡수돼서 붐비는 시간대에 3~5 dB 씩 더 깎입니다.
3. **다중경로(멀티패스)를 무시했습니다.** 실내에서 RSSI 가 튀는 가장 큰
   원인인데 결정론적 경로손실 모델로는 다룰 수 없습니다.
4. **4F 도면이 실제보다 넓습니다.** 슬래브 외곽이 2F·3F 와 같게 잡혀 있는데
   건축물대장상 4F 연면적은 7,921 ㎡ 입니다. 넓은 부분을 BOH 로 분류해서
   보행영역은 4,436 ㎡ 로 줄였지만, 4F 승강장 4곳이 그 BOH 안으로 들어가서
   화면에 빨간 점선으로 표시됩니다. 도면을 손보면 없어집니다.
5. **HDOP 은 2차원만 봅니다.** 층간 신호를 측위에 쓴다면 VDOP 도 필요합니다.
6. **체크포인트 위치는 승강장 축의 중앙점입니다.** 에스컬레이터 한 대의
   평면 footprint 중앙이라 양쪽 승강장에서 각각 7 m 쯤 떨어져 있습니다.
   포착반경(13~27 m) 안에 두 승강장이 모두 들어오므로 층 판별에는 문제가
   없지만, 실제로는 천장 구조물·조명·소방설비 때문에 그 자리에 못 달 수
   있습니다. 현장에서 드래그로 옮기고 고정하면 됩니다.

## 9. Claude API 를 붙이려면

지금은 백엔드가 없습니다. Claude API 는 **키가 노출되면 안 되므로 브라우저에서
직접 호출하면 안 됩니다.** Vercel 에 올리면 서버리스 함수를 공짜로 쓸 수 있으니
그쪽에 붙이면 됩니다.

프로젝트 루트에 `api/advise.js` 파일을 만들면 Vercel 이 자동으로
`/api/advise` 엔드포인트로 띄워줍니다. 키는 Vercel 대시보드의
**Settings → Environment Variables** 에 `ANTHROPIC_API_KEY` 로 넣습니다.

붙일 기능:

- **데이터시트 파싱** — 비콘 스펙 PDF/텍스트를 붙여넣으면 제원을 자동으로 채우기
- **자연어 제약** — "에스컬레이터 바로 위는 피해줘", "매장 안쪽은 최소한만"
  같은 문장을 설정값으로 번역
- **결과 해설** — 계산 결과를 읽고 취약 구역과 그 이유를 문장으로 설명

좌표 계산은 결정론적 알고리즘이 하고, Claude 는 **판단과 해석**을 맡는
하이브리드 구조입니다. 최적화 자체를 LLM 에 맡기면 재현성이 없어서
캡스톤 보고서에 쓸 수 없습니다.
